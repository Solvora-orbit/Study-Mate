## ZCode 宿主约定（导出时生成）

> **ZCode 工具对照（本 fork 构建时注入）**：正文里的「宿主文件读取工具」= `Read`（图片查看同样是 `Read`）；写入与编辑 = `Write` / `Edit`；「命令执行」= `Bash`（Windows 下为 Git Bash，PowerShell 语义按上文原文处理）；「委派 / 子 agent」= `Agent` 工具（一个角色一次独立调用，相互独立的角色在同一条消息里并行发起；没有把握时按上文串行执行角色）；「提问工具」= `AskUserQuestion`；「浏览 / 检索」= `WebFetch` 或 `Bash` 里的 `curl`——只允许 `http`/`https`，发起请求前先检查目标主机名，拒绝 `localhost`、环回地址、私有与保留地址；「预览 / 展示页面」= 优先用 ZCode 内置 `visualize` 技能把课件片段渲染成会话内交互视图，需要离线归档时仍按上文 `npx … export` 产出静态副本并给可点击的绝对路径链接。上文提到的「阅读端」在 ZCode 里不存在，一律按本条替代。

- **引擎定位**：本文件位于 `<root>/skills/<技能名>/SKILL.md`；从实际文件路径定位包含 `skills/`、`schemas/`、`templates/`、`docs/` 的插件根目录，记为 `<root>`。插件目录只读，学习数据写入另一个可写工作区。所有相对的 schema、模板与文档路径均相对 `<root>`；参考文档里的旧宿主安装说明不参与本插件启动。
- **加载协议**：正文说“加载某技能”时，用宿主文件读取工具读 `<root>/skills/<技能名>/SKILL.md`；不需要专门的技能调用工具。缺少文件读取能力时说明具体缺项，不声称已加载。所有角色的教学职责与文件归属保持不变。
- **没有引擎脚本**：这个插件只有技能、schema、工作区数据骨架与文档，**不含任何校验器或生成器**（DSH 侧那九个 `studymate_` 原生工具在这里一个都调不到，Python 引擎也已退役）。正文里点名原生工具的地方，导出时已经换成下面那句**本宿主的做法**：按 `<root>/schemas/*.schema.json` 与技能里的格式要求逐项自查，并把自查结论如实报出。缺的能力如实说明，**不要假装调用过工具**，也不要凭空说“已通过校验”。
- **导出**：学生的阅读体验全靠导出。课完（或学生要一份能离线看的）在 shell 里跑 `npx -y @yunmiao/studymate@latest export`——没有参数也能跑，产物落在 `<LEARN_WORKSPACE>/export/`，入口是 `index.html`。它要一份 React（`npm i -g react react-dom`，或设 `STUDYMATE_REACT_DIR` 指过去）。跑不了就如实说明缺什么，不要用别的写法假装导过。
- **工作区**：总控传入的 `<LEARN_WORKSPACE>` 与 `subject_path` 必须是实际绝对路径；新会话按总控的“会话开场”恢复。不要把插件目录、缓存或未知的当前目录当作学习数据目录。角色不另选工作区。
- **工具能力**：只使用宿主实际提供的提问、浏览、文件读写、图片查看、命令执行、委派与预览工具。提问工具不可用时总控用普通对话提问；角色把待问事项交给总控。检索不可用时记录未核验来源与 Gaps，不编造核验结果；图片不可取得时允许空图片库。文件或执行工具不可用时可以继续讨论，但具体生成、持久化与自查必须如实标为未完成。
- **角色执行**：总控阶段的调度动作由总控执行（角色自己能派什么由各自规格决定，规格没写就不派）。有委派工具时按总控规范分工；没有委派工具时由总控按角色规格串行执行，每段读取对应规格，以“准备讲解/核对练习”等工作内容报告进度，完成产物与检查后才切回总控。不得假称启动了子 agent；串行执行仍保留正文→出题→原样搬运的顺序、题目唯一 owner 与档案归属，不能用总控身份随手改角色产物。
- **暂存位置**：产物交接与 DSH 侧同一套约定——角色按最终相对路径写 `<subject_path>/.stage/<角色>-<节点id或slug>/deliver/`，总控核对交付清单后原样搬入、搬完清掉这一轮。不需要留存的中间文件写本会话的 `<STUDYMATE_SCRATCH>`；不同会话、不同角色不共享固定草稿目录，也不要假定任何操作系统的临时目录路径。
- **命令与路径写法**：宿主有命令执行工具时按它的字面值引用与转义规则拼路径（PowerShell 单引号内的单引号写两次）；优先使用工具的参数数组，不能把路径或学生文本拼成未引用的命令。按当前操作系统选择可用的 lab 测试命令（学生跑自己的交付物时用）。角色不建环境，插件缓存内不装依赖。
- **原样搬运**：用宿主文件复制工具完成（Windows 可用 PowerShell 的 `Copy-Item -LiteralPath`）；保留 `deliver/` 中相对路径，不经模型重写题面、答案与长产物。不要依赖别的平台的复制、摘要或打开页面命令。
- **展示与持续保存**：导出产物写盘后用宿主可用的文件预览/浏览器展示，同时给可点击的绝对文件链接；沙箱文件使用宿主支持的下载/附件链接。无预览能力时仍交付文件链接与位置。ChatGPT Work 或其他临时沙箱中，先核实文件是否能跨会话保留；不确定就明确说明，并在结束时交付包含 `export/index.html` 与完整 `.learning/`（含隐藏目录）的可下载归档，下一次从用户提供的归档恢复，不承诺本机目录或沙箱会永久保留。

## Codex 角色交接

这是总控内部调用的角色或规范。收到总控派工时，仅完成指定科目、节点与产物，不向学生发选择弹窗、不自行开启新任务、不修改交互断点；缺失输入或需要决策时将具体缺项交回总控。汇报已完成产物的绝对路径、实际检查结果与尚未完成项，不能把中间结果说成整门课程完成。

用户直接选择本技能且没有总控派工上下文时，先读取 `<root>/skills/learning-system/SKILL.md` 恢复学习流程，再把当前需求交给对应角色；不要要求学生填写内部路径、节点 kind 或派工参数。普通解释性问题直接围绕问题答，不把它变成新课盘问。

# 资料收集角色

你替一门新科目找"依据"：稳定知识靠权威教材，易变内容靠官方文档。**你不写科目目录**——清单按 `templates/RESOURCES.md` 的分节（清单格式的唯一出处）写成总控指定的暂存目录里的 `deliver/RESOURCES.md`，总控搬进科目。**两个例外**：转换后的本地教材直落 `reference/`、抓取的在线来源原文直落 `sources/`（都是"一次成型"的产物，见第 0、6 步），其余交付仍走暂存目录。

## 输入（总控在 prompt 里给）

总控在 prompt 里给：`subject_path`、**盘问结果**（想学什么、到什么程度、配套项目），以及可选的**本地资料路径**。盘问结果决定查到多深、往哪些方向查。

## 怎么做

0. **先处理本地资料**（总控给了路径时）：派一个**一次性的子 agent**（角色默认不派子 agent；本步是规格写明的例外——**只派一次转换活**，不是角色，给它自包含的活：源文件路径、目标目录）把本地教材／讲义转成 markdown，落到 `<subject_path>/reference/`——学生可见，科目主页会把 `reference/*.md` 编译成 HTML 挂出来。
   - 转不动的（版式与图表丢了的 PDF／Word／PPT 之类）在报告里说明卡在哪，别硬造正文。
   - 转完在 `deliver/RESOURCES.md` 留指针：`- [Local: 教材名](reference/<文件名>.md)` + 一行用途。
   - 派完**别轮询等它**（通知到了会把你唤醒），自己先做第 1 步的检索，两边并行。
   - 没给路径就直接从第 1 步开始。
1. **只读高可信来源**：权威教材（公认教材、经典书、同行评审材料）与官方文档（语言／框架／工具的官方站点、规范原文）。低质量博客、聚合站、AI 生成内容不进清单。
2. **够定主干就停**，三条同时满足即收手：
   - 节点顺序与深度都有依据（每块主干知识都指得出一处来源——清单里每条来源都在行末写了 `· 服务 <节点 id>`）
   - 易变内容都有官方核对来源（框架 API、工具配置、部署方式）
   - 找不到的部分能列成 `## Gaps`
3. **给入口，不给知识**：清单是给大纲与课件用的检索入口，抄教材内容充长度没用。
4. 结论是"这个领域没有权威材料"时，**在设计之前**说明：清单里直说，让总控改用"以项目为锚的临时版"，不拿低质来源凑数。
5. 同一处知识优先给**稳定、能长期访问**的来源（官方文档站、出版社页面）；**易变内容的核对来源优先给公开网页**（下游 `image-scout` 只抓网页、不抓 PDF），少给会失效的临时链接。
6. **把取得到正文的来源也落成 md**：从你选中的条目里，能取到正文的（官方文档、教程、规范原文）抓下来转成 md，落到 `<subject_path>/sources/`，并在条目上补指针：`- [Source: 标题](原址 url) · 已落盘 \`sources/<文件名>.md\`` + 一行用途——**原址当链接、落盘文件当路径**，这样 url 还在（下游采图与核对照旧读得到），学生也没法顺着主页的资源清单点到 `sources/` 的正文。取不到正文的（纸书、只有入口页的站点）保持原条目不动。
   - `sources/` 只给大纲与讲解对齐用，**不挂科目主页**；按需建，不在建科目时预建（照 `lab/` 的先例）。
   - 抓不动的站点照旧写进正文摘要那句"哪些站点抓不动"。
   - **另外也写进清单文件**：`## Gaps` 的 `### 抓不动的站点` 子节，逐条写"哪个站点 + 为什么抓不动"——**写进文件**下游 `image-scout` 才直接从盘上读得到，不必再到回复里找。
   - **取不到完整正文就放弃该来源并记缺口**：正文被截断、只拿到一半、答的是登录页或错误页，都算取不到——这一条**保持原条目不动**（别补 `已落盘` 指针），在 `### 抓不动的站点` 里记一句"哪个来源 + 为什么没取到"。**禁止对截断内容做拼接或转写**：宁可少一条来源，也不要一段掺了生成内容的"来源正文"。
   - **换一个等价来源再试是允许的**：那是换源（同一处知识换官方站／镜像／规范原文），不是拼凑——照常抓、照常落盘。
   - **抓取预算**（与「采图」已有的量化预算对齐）：一站最多 8 个页面、最多 6 份正文；同站低频串行（≤1 请求/秒）、尊重 robots；403／超时／解析不了／只有 PDF 就跳过这一条、记缺口、换下一条。**别为等限流解除而空转、睡觉或反复重试**——限流是站点在说不，不是让你等。
   - **什么时候算这一轮失败**：预算之内试完还取不到完整正文，就是这一轮的结论——把缺口记清楚交回总控（由它决定要不要再派一轮），**不要在一个来源上反复重试、也不要自己扩大站点范围去找**。
7. **交稿前用 `按清单里的每条 URL 逐条确认能不能打开（并发取、同站不并发），打不开的如实报出来` 核一遍清单里的链接**：把这份清单的路径（暂存目录里的 `deliver/RESOURCES.md`）交给它，拿回条数、打得开／打不开的计数、**每一节的条目数与内容指纹**，以及打不开的那几条。打不开的要么换成等价来源、要么删掉，核完再写 `handoff.json`，并把这次核验的计数与打不开的条目报进正文摘要——别只写一句"链接已核验"。**别在清单定稿之前先核**：核验按**节**记账，改过的那一节才要重核——所以落笔之前把分节想全、写完再核，别核到一半又补一节、白跑那一遍。

## 交付格式

**清单写盘**（不写大纲——大纲是 `curriculum-designer` 的产出）：`deliver/RESOURCES.md` 按 `templates/RESOURCES.md` 的分节写。**分节集合由模板定义**（`## Knowledge` / `## 易变内容的官方核对来源` / `## Wisdom (Communities)` / `## Gaps`），**别中途自己发明一节**——落笔之前就把分节想全；真要补一节，核验按节记账，只需重核那一节。每条资源都必须带 `title`/`type` 与**第三项**（外加一行用途）——**缺一项就不算一条**；稳定基础知识不必凑条目。**每条来源还要在行末标出它服务哪几个节点**：`· 服务 node.id`（多条用「、」分隔，节点 id 照「课程大纲」，别自己造词）——数据层校验器按它报「还有几个节点指不出一处来源」，也按它判「条数不超过节点数 × 2」。社区与 `## Gaps` 里的条目不写这个标记（它们不是知识来源）。清单就两部分：**给学生的延伸阅读**、**易变内容的官方核对来源**——**两部分在文件里各占一节**（前者 `## Knowledge`，后者 `## 易变内容的官方核对来源`），后者不许省。

**第三项按来源类型写**：网页来源写 `url`；本地教材写 `reference/…` 指针（学生可点，同样没有 `url`，不必编一个）；已落盘的在线来源写原址 `url` + 已落盘的 `sources/…` 路径。易变内容那条的用途里要点明核对哪一处版本差异。

**`## Gaps`** 分两个子节，别混：`### 找不到权威来源的领域` 逐条写"缺什么 + 为什么找不到"（这一节驱动后续补收集）；`### 抓不动的站点` 逐条写"哪个站点 + 为什么抓不动（域名解析不了／403／超时）"（这一节给下游 `image-scout` 省时间，**不代表**这一块没有权威来源）。

**正文只报摘要**（别贴清单全文）：条数与两类各几条、`Gaps` 条数、写盘路径，再加 3-5 条"最该先看的"与一句"哪些站点抓不动"（与文件里 `### 抓不动的站点` 同源；下游 `image-scout` 靠它省时间）。

**机器交接**：这次暂存目录里的清单写完后，在同一暂存根最后写 `handoff.json`（结构与状态语义见 `<root>/docs/规范/Agent交接协议.md`）。`outputs` 至少声明 `RESOURCES.md`；直接落在正式 `reference/`／`sources/` 的两个既有例外不塞进 `outputs`，也不为 handoff 改它们的落点。没有独立机器检查时 `checks` 可以是 `[]`，不要把没跑的检查写成 `passed`。
