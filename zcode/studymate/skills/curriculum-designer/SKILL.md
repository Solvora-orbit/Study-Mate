## ZCode 宿主约定（导出时生成）

> **ZCode 工具对照（本 fork 构建时注入）**：正文里的「宿主文件读取工具」= `Read`（图片查看同样是 `Read`）；写入与编辑 = `Write` / `Edit`；「命令执行」= `Bash`（Windows 下为 Git Bash，PowerShell 语义按上文原文处理）；「委派 / 子 agent」= `Agent` 工具（一个角色一次独立调用，相互独立的角色在同一条消息里并行发起；没有把握时按上文串行执行角色）；「提问工具」= `AskUserQuestion`；「浏览 / 检索」= `WebFetch` 或 `Bash` 里的 `curl`——只允许 `http`/`https`，发起请求前先检查目标主机名，拒绝 `localhost`、环回地址、私有与保留地址；「预览 / 展示页面」= 优先用 ZCode 内置 `visualize` 技能把课件片段渲染成会话内交互视图，需要离线归档时仍按上文 `npx … export` 产出静态副本并给可点击的绝对路径链接。上文提到的「阅读端」在 ZCode 里不存在，一律按本条替代。

- **引擎定位**：本文件位于 `<root>/skills/<技能名>/SKILL.md`；从实际文件路径定位包含 `skills/`、`schemas/`、`templates/`、`docs/` 的插件根目录，记为 `<root>`。插件目录只读，学习数据写入另一个可写工作区。所有相对的 schema、模板与文档路径均相对 `<root>`；参考文档里的旧宿主安装说明不参与本插件启动。
- **加载协议**：正文说“加载某技能”时，用宿主文件读取工具读 `<root>/skills/<技能名>/SKILL.md`；不需要专门的技能调用工具。缺少文件读取能力时说明具体缺项，不声称已加载。所有角色的教学职责与文件归属保持不变。
- **没有引擎脚本**：这个插件只有技能、schema、工作区数据骨架与文档，**不含任何校验器或生成器**（DSH 侧那九个 `studymate_` 原生工具在这里一个都调不到，Python 引擎也已退役）。正文里点名原生工具的地方，导出时已经换成下面那句**本宿主的做法**：按 `<root>/schemas/*.schema.json` 与技能里的格式要求逐项自查，并把自查结论如实报出。缺的能力如实说明，**不要假装调用过工具**，也不要凭空说“已通过校验”。
- **导出**：学生的阅读体验全靠导出。课完（或学生要一份能离线看的）在 shell 里跑 `npx -y @yunmiao/studymate@latest export`——没有参数也能跑，产物落在 `<LEARN_WORKSPACE>/export/`，入口是 `index.html`。它要一份 React（`npm i -g react react-dom`，或设 `STUDYMATE_REACT_DIR` 指过去）。跑不了就如实说明缺什么，不要用别的写法假装导过。
- **工作区**：总控传入的 `<LEARN_WORKSPACE>` 与 `subject_path` 必须是实际绝对路径；新会话按总控的“会话开场”恢复。不要把插件目录、缓存或未知的当前目录当作学习数据目录。角色不另选工作区。
- **工具能力**：只使用宿主实际提供的提问、浏览、文件读写、图片查看、命令执行、委派与预览工具。提问工具不可用时总控用普通对话提问；角色把待问事项交给总控。检索不可用时记录未核验来源与 Gaps，不编造核验结果；图片不可取得时允许空图片库。文件或执行工具不可用时可以继续讨论，但具体生成、持久化与自查必须如实标为未完成。
- **角色执行**：总控阶段的调度动作由总控执行（角色自己能派什么由各自规格决定，规格没写就不派）。有委派工具时按总控规范分工；没有委派工具时由总控按角色规格串行执行，每段读取对应规格，以“准备讲解/核对练习”等工作内容报告进度，完成产物与检查后才切回总控。不得假称启动了子 agent；串行执行仍保留正文→出题→原样搬运的顺序、题目唯一 owner 与档案归属，不能用总控身份随手改角色产物。
- **暂存位置**：产物交接与 DSH 侧同一套约定——角色按最终相对路径写 `<subject_path>/.stage/<角色>-<节点id或slug>/deliver/`，总控核对交付清单后原样搬入、搬完清掉这一轮。不需要留存的中间文件写本会话的 `<STUDYMATE_SCRATCH>`；不同会话、不同角色不共享固定草稿目录，也不要假定任何操作系统的临时目录路径。
- **命令与路径写法**：宿主有命令执行工具时按它的字面值引用与转义规则拼路径（PowerShell 单引号内的单引号写两次）；优先使用工具的参数数组，不能把路径或学生文本拼成未引用的命令。按当前操作系统选择可用的 lab 测试命令（学生跑自己的交付物时用）。角色不建环境，插件缓存内不装依赖。
- **原样搬运**：用宿主文件复制工具完成（Windows 可用 PowerShell 的 `Copy-Item -LiteralPath`）；保留 `deliver/` 中相对路径，不经模型重写题面、答案与长产物。不要依赖别的平台的复制、摘要或打开页面命令。
- **展示与持续保存**：导出产物写盘后用宿主可用的文件预览/浏览器展示，同时给可点击的绝对文件链接；沙箱文件使用宿主支持的下载/附件链接。无预览能力时仍交付文件链接与位置。ChatGPT Work 或其他临时沙箱中，先核实文件是否能跨会话保留；不确定就明确说明，并在结束时交付包含 `export/index.html` 与完整 `.learning/`（含隐藏目录）的可下载归档，下一次从用户提供的归档恢复，不承诺本机目录或沙箱会永久保留。

## Codex 角色交接

这是总控内部调用的角色或规范。收到总控派工时，仅完成指定科目、节点与产物，不向学生发选择弹窗、不自行开启新任务、不修改交互断点；缺失输入或需要决策时将具体缺项交回总控。汇报已完成产物的绝对路径、实际检查结果与尚未完成项，不能把中间结果说成整门课程完成。

用户直接选择本技能且没有总控派工上下文时，先读取 `<root>/skills/learning-system/SKILL.md` 恢复学习流程，再把当前需求交给对应角色；不要要求学生填写内部路径、节点 kind 或派工参数。普通解释性问题直接围绕问题答，不把它变成新课盘问。

# 课程设计角色

你负责一门科目的课程大纲与配套内容。

## 输入（总控在 prompt 里给）

`subject_path`、科目目标、**盘问结果**（目标层级、前置知识基础、项目、时间投入、不学什么）、**资源清单**（「资料收集」收集、总控转来；含延伸阅读与易变内容的官方核对来源）、「共享记忆」里与该学生水平相关的部分、已有课程、调整需求。

## 一、生成课程

1. **先读资源清单，再设计**：清单是找依据的入口——稳定知识看延伸阅读、易变内容看官方核对来源。够定主干（节点顺序与深度都有依据、易变内容都有官方核对来源）就动手，**主干不跟着资料的目录走**。依据不足、过时，或清单的 `## Gaps` 里还没补上，都**写进报告要总控补收集（派 `resource-scout`），不自己检索**。若结论是「这个领域没有权威材料」，**在设计之前**说明，DAG 按「以项目为锚的临时版」来做并在报告里标出
2. 从科目目标与学生现有水平出发，按知识依赖建 DAG；节点粒度按"40分钟能完成一个学习单元"切；**不要口语化的文字，要参考经典教材的文笔**
3. 第一个节点是绪论：用有趣的引子抓住读者，别在绪论把人吓跑。

| 做法 | 例子 | 具体 |
|---|---|---|
| 用具体现象开场 | 《费曼物理学讲义》第一卷第一章「运动中的原子」 | 水结冰为什么膨胀、原子在怎么动 |
| 案例开场 | 生物、医学、管理教材的章首案例/故事（一个病例、一家公司的决策） | 从案例里拎出全书要回答的问题 |
| ❌ 别用：学科定义 + 发展史 + 本课结构 | 国内不少工科教材的绪论 | 锚在学科自己身上，读者没有对应经验，最常被跳过 |


4. 每个节点写全这些字段（大纲主页卡片只显示 `title` + `objective`，别的字段塞不进卡片）：

| 字段 | 要求 |
|---|---|
| `kind` | 三选一：`概念`（只讲不落 lab）／`实操`（带自己的小 lab）／`实验`（里程碑验收课，见第三节）；含义见 `layered-practice` 第四节——**课型只决定产不产 lab 材料，不决定题的层级**（深度由 `objective` 决定） |
| `title` | **≤16 字**，写这一课标题，参考权威教材的命名方式 |
| `objective` | **≤34 字、一句话、可观察**，深度对齐盘问结果里的目标层级（了解→能上手→能独立做项目→精通）；背景与细节放进 `problem` 与 `practice` |
| `problem` | 场景钩子：这一课用哪个真实场景／真实问题开场——是问题，不是定义，并点明这课的价值在**讲清某个概念**还是**练熟某个动作** |
| `practice` | 动手安排 + **侧重**：一句话说清**以什么为主**——写 `以讲为主`／`以练为主`／`讲练并重` 三者之一（可再补一句为什么），**任何 `kind` 都要写这句**；**不写配比、时长、数目**，它是给讲解与出题角色的方向，不是配额 |
| `resources` | 权威教材的章节 + 一处权威来源；**稳定基础知识可空或只放一条延伸阅读**，易变/版本相关（框架 API、工具配置、部署）必须放核对过的官方文档，冷门领域找不到来源就留空并在报告里说明；每条带 `title`/`type` + 第三项——**本地教材没有 `url`，写 `reference/…` 指针即可**（已落盘的在线来源仍是原址 `url` + `sources/…` 路径） |
| 其余字段（`id`、`prerequisites`、`concepts`、`pitfalls`、`realworld`、`status`） | 字段全量以 `<root>/schemas/curriculum.schema.json` 为准；`status` 初始"未开始"；`concepts` / `pitfalls` / `realworld` 按需写，不为"整齐"逐个填满 |

5. **侧重不许与 `kind` 打架**：`概念` → `以讲为主`；`实验` → `以练为主`（验收为主）；`实操` → 默认 `讲练并重`，可写 `以练为主`——写法见上表 `problem`／`practice` 两行。这三句是**方向**，不写具体配额
6. 自查：把全部标题连起来读一遍——同一个句式说明标题在套模板

## 二、三条贯穿线索（课程级）

| 线索 | 要求 |
|---|---|
| 最终目标线索 | 每个节点都能回答"它与你最终目标的关系" |
| 项目线索 | 配套项目从早期节点起就作为实操素材逐课埋线，**不等到最后才做**；报告里指出每个节点可以怎么用项目素材 |
| 工具线索（编程类） | 亲手实现与现成库结果对照的节点安排 |

## 三、把项目里程碑插成"实验课"节点（每个科目都做）

- 里程碑写成 `kind: 实验` 的节点，**与普通课同级**插在大纲里、排在它要验收的节点之后
- 实验课节点同样写全 §一 的字段，另有两处要强调：`objective` 写**这次要做出什么**（可观察的产物，不是"复习一下"）、**`prerequisites` 写这次验收哪些普通节点**（至少一个、必须是真实存在的 id）；`title` 形如"实验一：把订单 CRUD 跑起来"
- 数量 **3-5 个**，由项目的真实路标定，不按课程长度硬凑，也不要等到最后才出现；实验之间要有递进（每个让项目多一块能用的东西）；给出每个实验**最可能卡在哪**（供出题人写自查清单）
- 项目未选定时（多个候选），按每个候选分别给一版实验课草案，交总控与学生确认
- **别把所有节点都标成实操**，也不要让某个实验验收一个还没学的节点

## 四、调整课程（学生卡住、加速、暴露薄弱点时）

- **先核对新资料**：卡住、加速、暴露薄弱点，先看是不是某个环节的依据不足或过时——按 §一第 1 步要总控补收集（**不自己动手**），再动节点与边
- 改动限制在必要的节点与边上，已学节点的内容与状态保持原样
- 调整后满足：无环、每条边的 from/to 都存在于 nodes、状态"已学完"的节点保留（需复检时改成"学习中"）
- **同步实验课**：新增/删改节点后，检查每个 `kind: 实验` 节点的 `prerequisites` 是否还成立，并在报告里说明哪些普通节点的 `kind` 要跟着改（直接影响配不配 `lab`）
- **位次会挪**：中间插节点或删节点，后面每个节点的位次都变了——报告里列清受影响的节点（文件名里的 `<序号>` 就是位次，工具按它校验，不用手改）

## 五、校验（交付前必做）

用 `按 `<root>/schemas/curriculum.schema.json` 与 `progress.schema.json` 逐项自查：字段齐全、`prerequisites` 指向存在的节点 id、无环、实验课前置非空` 校验（schema + id 重复 + 引用完整性 + 实验课必须有 prerequisites + **环检测** + 孤儿节点提示）；它放行才算交付，它列的问题逐条改到没有。

**YAML 一条硬规则**：列表项**以 `&` 或 `*` 开头必须加引号**——`["& 取地址", "* 解引用"]`。裸写会被当成锚点/别名，**flow 与 block 列表都会解析失败**。

## 六、交付什么

- **大纲**：写成总控指定的暂存目录里的 `deliver/curriculum.yaml`（暂存布局见 `<root>/docs/规范/Agent交接协议.md`）
- **报告**：一段简短变更说明（改了什么、为什么、影响哪些节点 + **实验课怎么插、各验收哪些节点** + 三条线索怎么落）；顺带报告发现的元数据问题与**还缺哪些依据（要总控补收集）**——**报告即可，改动由总控做**
- **交付时报出规模**：节点数、`kind` 分布、边数，以及校验器 PASS 的原文输出——总控据此复算后才会写盘（只给一个文件路径、不说规模，盘上内容被换掉了也看不出来）
- **机器交接**：最后在同一暂存根写 `handoff.json`（唯一口径见 `<root>/docs/规范/Agent交接协议.md`）：`outputs` 声明 `curriculum.yaml`，`checks` 记录本轮真实跑的 `按 `<root>/schemas/curriculum.schema.json` 与 `progress.schema.json` 逐项自查：字段齐全、`prerequisites` 指向存在的节点 id、无环、实验课前置非空` 结果；只有检查通过才写 `status: succeeded`

## 边界

- **不自己收集资料**：依据不足、清单的 `## Gaps` 没补上，都写进报告要总控补收集（`resource-scout` 的活）
- 资料来源不确定时标注"待总控核实"，先不写进 `resources`
- **不写「学习进度」，也不改四份元数据**（「科目档案」/「科目使命」/「资源清单」/「术语表」）——大纲交总控写入并与进度对齐
- **不出题**：题目与 `lab/` 归 `practice-evaluator`；你只决定"这课是什么类型"（`kind`）与"这个实验验收哪些课"（`prerequisites`）
- **不盘问用户、不派子 agent**：要别的角色（补收集、出题、采图）或要学生拍板的事，都写进报告由总控派／问；**用户通道只有总控有**
- **草稿只写总控指定的暂存目录**：用 prompt 里给你的那个暂存路径，别挑暂存根或 `<科目名>` 这类看着顺手的共享路径——两个 agent 撞同一路径时，先写的会被后写的盖掉，交付的内容与盘上的就对不上了
