## ZCode 宿主约定（导出时生成）

> **ZCode 工具对照（本 fork 构建时注入）**：正文里的「宿主文件读取工具」= `Read`（图片查看同样是 `Read`）；写入与编辑 = `Write` / `Edit`；「命令执行」= `Bash`（Windows 下为 Git Bash，PowerShell 语义按上文原文处理）；「委派 / 子 agent」= `Agent` 工具（一个角色一次独立调用，相互独立的角色在同一条消息里并行发起；没有把握时按上文串行执行角色）；「提问工具」= `AskUserQuestion`；「浏览 / 检索」= `WebFetch` 或 `Bash` 里的 `curl`——只允许 `http`/`https`，发起请求前先检查目标主机名，拒绝 `localhost`、环回地址、私有与保留地址；「预览 / 展示页面」= 优先用 ZCode 内置 `visualize` 技能把课件片段渲染成会话内交互视图，需要离线归档时仍按上文 `npx … export` 产出静态副本并给可点击的绝对路径链接。上文提到的「阅读端」在 ZCode 里不存在，一律按本条替代。

- **引擎定位**：本文件位于 `<root>/skills/<技能名>/SKILL.md`；从实际文件路径定位包含 `skills/`、`schemas/`、`templates/`、`docs/` 的插件根目录，记为 `<root>`。插件目录只读，学习数据写入另一个可写工作区。所有相对的 schema、模板与文档路径均相对 `<root>`；参考文档里的旧宿主安装说明不参与本插件启动。
- **加载协议**：正文说“加载某技能”时，用宿主文件读取工具读 `<root>/skills/<技能名>/SKILL.md`；不需要专门的技能调用工具。缺少文件读取能力时说明具体缺项，不声称已加载。所有角色的教学职责与文件归属保持不变。
- **没有引擎脚本**：这个插件只有技能、schema、工作区数据骨架与文档，**不含任何校验器或生成器**（DSH 侧那九个 `studymate_` 原生工具在这里一个都调不到，Python 引擎也已退役）。正文里点名原生工具的地方，导出时已经换成下面那句**本宿主的做法**：按 `<root>/schemas/*.schema.json` 与技能里的格式要求逐项自查，并把自查结论如实报出。缺的能力如实说明，**不要假装调用过工具**，也不要凭空说“已通过校验”。
- **导出**：学生的阅读体验全靠导出。课完（或学生要一份能离线看的）在 shell 里跑 `npx -y @yunmiao/studymate@latest export`——没有参数也能跑，产物落在 `<LEARN_WORKSPACE>/export/`，入口是 `index.html`。它要一份 React（`npm i -g react react-dom`，或设 `STUDYMATE_REACT_DIR` 指过去）。跑不了就如实说明缺什么，不要用别的写法假装导过。
- **工作区**：总控传入的 `<LEARN_WORKSPACE>` 与 `subject_path` 必须是实际绝对路径；新会话按总控的“会话开场”恢复。不要把插件目录、缓存或未知的当前目录当作学习数据目录。角色不另选工作区。
- **工具能力**：只使用宿主实际提供的提问、浏览、文件读写、图片查看、命令执行、委派与预览工具。提问工具不可用时总控用普通对话提问；角色把待问事项交给总控。检索不可用时记录未核验来源与 Gaps，不编造核验结果；图片不可取得时允许空图片库。文件或执行工具不可用时可以继续讨论，但具体生成、持久化与自查必须如实标为未完成。
- **角色执行**：总控阶段的调度动作由总控执行（角色自己能派什么由各自规格决定，规格没写就不派）。有委派工具时按总控规范分工；没有委派工具时由总控按角色规格串行执行，每段读取对应规格，以“准备讲解/核对练习”等工作内容报告进度，完成产物与检查后才切回总控。不得假称启动了子 agent；串行执行仍保留正文→出题→原样搬运的顺序、题目唯一 owner 与档案归属，不能用总控身份随手改角色产物。
- **暂存位置**：产物交接与 DSH 侧同一套约定——角色按最终相对路径写 `<subject_path>/.stage/<角色>-<节点id或slug>/deliver/`，总控核对交付清单后原样搬入、搬完清掉这一轮。不需要留存的中间文件写本会话的 `<STUDYMATE_SCRATCH>`；不同会话、不同角色不共享固定草稿目录，也不要假定任何操作系统的临时目录路径。
- **命令与路径写法**：宿主有命令执行工具时按它的字面值引用与转义规则拼路径（PowerShell 单引号内的单引号写两次）；优先使用工具的参数数组，不能把路径或学生文本拼成未引用的命令。按当前操作系统选择可用的 lab 测试命令（学生跑自己的交付物时用）。角色不建环境，插件缓存内不装依赖。
- **原样搬运**：用宿主文件复制工具完成（Windows 可用 PowerShell 的 `Copy-Item -LiteralPath`）；保留 `deliver/` 中相对路径，不经模型重写题面、答案与长产物。不要依赖别的平台的复制、摘要或打开页面命令。
- **展示与持续保存**：导出产物写盘后用宿主可用的文件预览/浏览器展示，同时给可点击的绝对文件链接；沙箱文件使用宿主支持的下载/附件链接。无预览能力时仍交付文件链接与位置。ChatGPT Work 或其他临时沙箱中，先核实文件是否能跨会话保留；不确定就明确说明，并在结束时交付包含 `export/index.html` 与完整 `.learning/`（含隐藏目录）的可下载归档，下一次从用户提供的归档恢复，不承诺本机目录或沙箱会永久保留。

## Codex 内部规范

本文件是供当前执行者读取的规范；加载它不创建新角色，也不改变调用者身份。总控可以按本规范答疑、维护档案和交互断点；委派角色仍只完成自己的产物，不接管学生对话或总控档案。用户直接选择本规范来继续学习时，先读 `<root>/skills/learning-system/SKILL.md` 并恢复当前学习位置，不从头盘问。

# 课件设计规范

**本文件管课件内核与内容写法，不管版式**：分节、标题、例子与代码块的位置由讲解角色按内容与学生偏好定，「共享记忆」的个人偏好优先。页头、顶栏、主题开关、脚本由渲染器统一产出。题目、lab、实验说明页也不归本文件管（题目与 lab 见 `layered-practice`）。

## 一、着眼点（弱约束：按实际情况调整，不必强加内容）

1. **参考**：课件的结构与内容可参考科目「资源清单」收集到的认可度高的教材；缺的来源报给总控
2. **术语**：讲解术语时可以先讲它的历史来由，再给严格的形式化定义。
3. **深度**：讲透前提、推导、边界与反例，不做速成课；简洁不等于浅
4. **练习**：`kind: 实操` → 引导式实操（任务与断言由 `practice-evaluator` 出、落在 `lab/`，内容文件里对应一个练习块，位置与引入由你定）；`kind: 概念` → 轻量练习（敲一条命令、改一行看变化、在输出里指出某个东西；不落 lab、不算交付物、每步立刻能看到结果）；练习块与练习步骤的标题按内容写**中文阶段名**，**不要用 L1-L4 标步骤**（那是题目的层级词汇）

## 二、线索

三条线索：**最终目标**（与「科目使命」的关系）、**配套项目**（从早期就逐课埋线，当实操素材）、**工具对照**（编程类：亲手实现与现成库对照）。

## 三、复用与骨架（硬约束）

块名与用途见下表；语法以 `<root>/docs/规范/课件内容格式.md` 为准（本文件不复述）。

| 要讲的东西          | 用哪个块                                | 设计标准                                                                    |
| -------------- | ----------------------------------- | ----------------------------------------------------------------------- |
| 一节             | `## 标题`                             | ≤14 字（进左侧目录），一节一个着眼点；句式服从内容，不套模板                                        |
| 分点、步骤、对照       | `-` 列表 / 管道表                        | 对照关系（说法 ↔ 写法 ↔ 边界）用表，其余用列表；列表项不写长段落                                     |
| 代码与终端          | ` ```lang ` 围栏（要框内解释就用 `::: code`） | 讲的代码要能跑；语言标签写清楚；`::: code` 的写法见规范 §4                                    |
| 练习块            | `::: practice <层级> \| <标题>`         | 按「练习」那条着眼点安排                                                            |
| 题目位置           | `::: quiz <层级> 锚点：<锚点文本>`           | 只留位、不写题：题由 `practice-evaluator` 出，锚点文本逐字给它                              |
| 提示 / 警告 / 中性提示 | `::: tip` / `::: warn` / `::: note` | 用在真会绊倒学生的地方，不拿它凑版面                                                      |
| 配图             | `::: figure <相对路径>`（内联示意图另有 `::: svg`） | **图要够丰富**（见下）；来源、怎么画、`alt:`/`caption:` 写法与尺寸见 `learning-coach` 的「配图」 |
| 资源与相关课件        | `::: resources` / `::: related`     | 只放真会去用的；给不出链接的参考书写成不带链接的条目                                              |

**该配图的地方不要只用文字带过**："前后对比、参数影响、结构/流程关系、数据分布"这类内容，用图比用文字省力——但图不是装饰，说不清的地方配一张不算丰富。**配不配、配几张由内容定；画法不限**（内联示意图、脚本出图、从「图片库」挑现成图都行，来源与做法见 `learning-coach` 的「配图」）。

**一节的组织**：一个 `##` 一节，先场景与来历、再定义、再例子与代码、最后练习或题目位置收尾。

| 硬约束 | 怎么做 |
|---|---|
| 起点 | 先读 `<subject_path>/assets/` 组件库（复用样式与术语） |
| 文件名 | `<序号>-<节点id>.md`，序号 = 本节点在「课程大纲」的 `nodes:` 里排第几（4 位补零，如 `0003`）、节点 id 原样照抄——上一课的「下节课」指针按这条规则预写 |
| 归属 | 只认文件名：这课是哪个节点、挂主页路线图哪个位置；页头的 eyebrow 是给学生看的可读文字（`0001 · 第一份能提交的代码`），写不写节点 id 都不影响归属 |
| 上/下节课指针 | 渲染器按「课程大纲」的 `nodes:` 顺序算（第一课没有上一个、最后一课没有下一个） |
| 顶栏与主题开关 | 顶栏、主题开关、脚本引用由渲染器产出；内容文件里出现块级 HTML 标签会被渲染器拦下 |
| 交付形态 | 内容文件 + 出题人的题库，渲染出的页面自包含（相对路径引用共享层与科目组件）、浏览器直开可用、适合反复回看 |

## 四、行文要求

1. **避免使用「肯定-否定」句式或转折句式，如「不是X而是Y」**：避免只用于抬高语气的假对比。两部分都提供信息，或否定部分纠正真实误解时保留。
  **错误：** 这不仅是一个导出按钮，更是通往高效工作的全新入口。它可以导出 CSV。
  **正确：** 这个按钮可以导出 CSV。
  **保留：** 错误发生在保存阶段，而不是上传阶段。
2. **格言与伪深度**：如「X是从Y长出来的」；修辞没有增加意思时，回到原文已有的具体判断。比喻含义不清时，不替用户猜出一种新论点。
  **错误：** 编译落到你手上，就是一个具体动作，比如把一个cpp文件转换成一个可执行的.exe文件
  **正确：** 比如把一个cpp文件转换成一个可执行的.exe文件，这就是编译。
  **保留：** 被引用、被分析的格言，以及作者有意使用且能帮助理解的比喻。
3. **不要假想敌辩论**：删除没有具体内容的自我辩护。真实反对意见、限制条件和读者确实会考虑的方案要保留。
  **错误：** 不要误会，我并不是在制造焦虑。我想说的是，删除前需要确认备份是否存在。
  **正确：** 删除前需要确认备份是否存在。
  **保留：** 这项措施不能防止断电，但可以减少断电后的数据损失。
4. **用陈述替代铺垫，减少信息碎片**：合并重复同一意思的碎片，删除不增加内容的收尾。短句承载新事实或需要有意强调时保留。
  **错误：** 分解能不能用在真正大的问题上，取决于它要花多少运算。这个问题可以问得很具体：一千个未知数的方程组，计算机一秒能解完、还是要等一星期？要回答它，得先数清每一步在改多少个数字。
  **正确：** 分解的实用性取决于他的运算速度，就比如看一千个未知数的方程组在计算机里能不能一秒解完
  **保留：** 本节先给出定义,再通过两个例子说明其用法,最后讨论常见误区。
5. 非重点的章节或课程无须写得太详细。重点不明确会显著提高阅读负担
6. **不得将未学过的知识点放入当前课件**，常见情况为「引入用户不知道的库或命令」「把用户没学过的东西放代码里面用」「大量的使用未学过的术语」，请把读者当作一个理解能力稍强的16岁学生，切记**读者不是全知全能的AI**
7. **不要过度口语化**，应当严格遵守下文的**教材式行文风格**
8. **交付前需重读交付物**，检查是否存在上述行文要求

## 五、行文风格

请以经典教材的**教学性说明文体**（didactic exposition）和**教科书语体**（textbook register）写作：以说明为主、辅以必要论证，保持学术语域与术语一致，术语第一次出现时先讲来历再给**形式化定义**，再用元话语和衔接把定义、例证、对比、小结等修辞关系自然串起来，借助脚手架式推进让读者从具体到抽象、由已知到未知地理解，语气克制、客观、清晰，少用口语、情绪和营销化表达，读起来像一本严谨、清晰、可自学的经典教材；例如可以这样落笔：「设函数 f 在区间 I 上有定义。若对任意 $x_1,x_2 \in I，当 x_1<x_2$ 时都有 $f(x_1) < f(x_2)$，则称 f 在 I 上严格递增。」「直观上，这意味着函数值随自变量增大而增大；但需要注意，单调性总是相对于某个区间而言的。」「本节先给出定义，再通过两个例子说明其用法，最后讨论常见误区。」
